# Motion Plan · `site/index.html`

Описано только то, что реально есть в файле. Никаких пожеланий — только наблюдаемое поведение.

В коде два `@keyframes`-блока и одна ветка `prefers-reduced-motion`. Движение описано как текущее поведение реализации. Согласование бегущей строки владельцем не зафиксировано.

## 1. Появление первого экрана — `rise`

**Где:** правило `.hero-text > *` + `.hero-portrait img` (CSS, без JS).
**Что двигается:** пять прямых детей `.hero-text` (рубрика, H1, лид, ряд CTA, условия) поднимаются снизу и проявляются. Портрет справа поднимается и проявляется чуть позже.
**Триггер:** автоматически при загрузке страницы. Никаких классов, никаких слушателей — стиль стартует сразу, потому что `animation` применяется к существующим узлам.
**Длительность:** 0.7s для текста, 0.9s для портрета. Easing — `cubic-bezier(.2,.7,.3,1)`. `animation-fill-mode: both` — стартовое состояние `opacity:0; transform:translateY(18px)` сохраняется до начала.
**Стаггер:** `nth-child(2..5)` у `.hero-text` получают задержки `.07s, .14s, .21s, .28s`. У портрета — `.1s` сверх того.
**`prefers-reduced-motion: reduce`:** в `@media`-блоке `animation:none` для обоих селекторов. Контент появляется сразу в финальной позиции.
**Без JS:** работает как есть. JS не задействован.

## 2. Бегущая строка — `marquee`

**Где:** `.marquee-track` (CSS).
**Что двигается:** трек `.marquee-track` едет справа налево. Содержимое продублировано (5 пунктов × 2 раза подряд), чтобы зацикливание было бесшовным: анимация `transform: translateX(0) → translateX(-50%)`, ширина трека — `max-content`.
**Триггер:** автоматически при загрузке.
**Длительность:** 30s, `linear`, `infinite`.
**Пауза:** `.marquee:hover .marquee-track` и `.marquee:focus-within .marquee-track` ставят `animation-play-state: paused`. Контейнер помечен `aria-hidden="true"` (декоративный), но пауза на ховере нужна и для тех, кто его случайно «читает».
**`prefers-reduced-motion: reduce`:** в `@media`-блоке `.marquee-track { animation:none; transform:none }`. Полоса просто стоит как обычный текст.
**Без JS:** работает без JavaScript.

## 3. Появление блоков при скролле — `.reveal` / `.is-in`

**Где:** стили `.js .reveal` (CSS) + IIFE рядом со строкой 432 (JS).
**Что двигается:** все элементы с `.reveal` — заголовки секций, тела, форматы, шаги, FAQ-блоки, финальная секция, портрет и текст личного блока. Стартовое состояние — `opacity:0; transform:translateY(22px)`. Финальное (`.is-in`) — `opacity:1; transform:none`.
**Триггер:** один раз при попадании в зону видимости (`IntersectionObserver`, `rootMargin: '0px 0px -8% 0px'`, `threshold: 0.08`). После срабатывания элемент `unobserve`-ится — повторно не триггерится.
**Длительность:** 0.6s, `ease` — для opacity и transform.
**Активация JS:** в начале скрипта `document.documentElement.classList.add('js')`. Все `.reveal`-стили скрыты под `.js`-префиксом, поэтому до загрузки/исполнения скрипта элементы видны как есть.
**`prefers-reduced-motion: reduce`:** JS-код сначала проверяет `matchMedia('(prefers-reduced-motion: reduce)').matches` — если да, сразу всем `.reveal` добавляется `.is-in`, `IntersectionObserver` не создаётся. Плюс CSS-ветка дополнительно глушит переход: `.js .reveal { opacity:1; transform:none; transition:none }`.
**Без `IntersectionObserver`:** тот же ранний выход — все сразу получают `.is-in`.
**Без JS вообще:** `.js` не добавляется → стили `.js .reveal` не действуют → элементы сразу видны без анимации.

## 4. Шёпот стрелок в форматах и личном блоке

**Где:** `.fmt-go i` и `.me-link i` (CSS).
**Что двигается:** иконка-стрелка `→` сдвигается на 7px вправо при наведении/фокусе на родительской ссылке.
**Длительность:** 0.25s, `ease`.
**`prefers-reduced-motion: reduce`:** `transition:none; transform:none`. Стрелка не двигается.
**Без JS:** работает как есть (чистый CSS hover/focus-visible).

## Общий итог

- Все четыре приёма реализованы CSS или маленьким ванильным JS-блоком. Никаких сторонних библиотек, никакого parallax, никакого scroll-jacking.
- HTML `scroll-behavior: smooth` для якорей; в `@media(prefers-reduced-motion:reduce)` — `scroll-behavior: auto`. Это тоже про движение (резкий прыжок к якорю считается движением для пользователя).
- Без JS сайт полностью функционален: мобильное меню раскрыто по умолчанию, секции видны без подсветки, бегущая строка и появление первого экрана работают на чистом CSS. JS только добавляет улучшения, которые аккуратно снимаются `prefers-reduced-motion`.
